# R01: fresh candidate gate — Azure smoke validated

Status: Ready for review. Tested live source: `2ea7b67cde2ef15fae23687e7391d017be503301`.
The later handoff commit changes documentation/evidence only. No push or remote
Actions run occurred. This is public reference work, not commercial deployment proof.

On 17 October 2026 the actual application ingested 11 sample documents into 41
chunks in Azure AI Search Free. A three-question baseline passed; a controlled
failure using the actual retrieved sources and an injected unsupported answer
failed. Baseline mean relevance, groundedness, coherence and fluency were each
5/5. Failure means were 3.667, 1.0, 3.333 and 4.0 respectively. The gate blocked
the failure on per-case and mean quality checks without changing thresholds.
This is a tiny smoke check, not a held-out benchmark or population calibration.
B01 remains deferred. Same-model generation/judging can share blind spots.

## Method and evidence boundary

`fresh_quality.py` calls the actual application and a custom Azure OpenAI JSON
rubric (`azure-openai-custom-four-score-v1`), not Microsoft built-in evaluators
or RAGAS. One judge response supplies four scores for each generated answer.
Generation/judging used gpt-4.1-mini version 2025-04-14; embeddings used
text-embedding-ada-002 version 2 (1536 dimensions). All paid work ran on CPython
3.11.17 after a clean `pip install -e ".[dev]"` installation.

The runner writes an expectation manifest before inference, then records actual
answers, sources, scores, errors and recomputed means. Source/configuration/
dataset/corpus hashes, case identities and run UUID bind evidence to a candidate.
The gate enforces a one-hour freshness window and rejects malformed, missing,
nonfinite, partial or internally inconsistent evidence. Live negative checks
rejected wrong source revision, configuration hash, run UUID, stale timestamp
and missing groundedness. Offline adapters cannot satisfy a live gate.

Pilot floors are mean relevance/groundedness >=4, coherence/fluency >=3 on a 1–5
scale; any per-case score below 2 is critical. These are provisional engineering
requirements, not statistically calibrated thresholds or E04's different rubric.
The fault adapter replaces generated output after the actual application call;
it is a controlled drill, not a second deployed commit or observed incident.
Index revision is an operator assertion, not immutable remote-content proof.
Hashes establish identity, not truth or signatures. A release authority must
supply trusted expectations and trust the runner; report metadata alone cannot
establish integrity. Historical reports cannot satisfy a new release gate.

## Resource lifecycle and budget

The user selected Free-tier Search within the shared USD 10 ceiling. The existing
empty Free Search service was reused with a unique task index. Existing Azure
OpenAI account and resource group were retained. Two temporary Standard
pay-per-token model deployments supplied enough request quota; these were not
provisioned-throughput deployments or a paid Search tier.

The first attempt hit RateLimitError using the original low-quota embedding
deployment; the second hit NotFoundError immediately after model creation.
The successful attempt recorded DeploymentNotFound on its first readiness probe
and succeeded after a bounded wait. All three attempts' receipts are retained;
cleanup was verified for every task-created index and temporary model deployment.
No existing service, group or model deployment was deleted.

Actual teardown used `SearchIndexClient.delete_index(<unique task index>)` and
`az cognitiveservices account deployment delete --name ai103-openai
--resource-group ai103-rg --deployment-name <unique task deployment>` (explicit
subscription supplied by the runner). Index/deployment lists then verified
absence. Do not delete the pre-existing group or shared services.

Each run reserved before inference with max 30 attempts, USD 2 allowance, 64KB
request limit, 512 output tokens per generation/judge, and disabled SDK retries.
Failed calls retain reservations. Allowance rates are USD 2/M chat input, 10/M
chat output and 1/M embedding input: conservative budgeting assumptions, not
an exact Azure retail quote or invoice. Failed-call billed usage is unknown.

Across all R01 attempts: 23 attempted calls; USD 0.128210 reserved;
USD 0.011789 conservative usage calculation for returned usage only.
E04/E05 previously estimated USD 0.002301 separately. The aggregate accounting
allowance remains below USD 10; actual billing reconciliation is pending.

review its subscription, existing resource names and absolute workspace paths
